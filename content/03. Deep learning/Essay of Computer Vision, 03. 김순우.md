## 도메인 적응 객체 탐지
- DAOD : 객체 탐지에 문제를 해결하기 위해서 ? → Yolo나 학습된 데이터에서 외부 데이터에 성능이 떨어지는 문제가 생김.
- 소스 도메인과 타겟 도메인 간의 차이를 완화함. → 공통된 특징 
- 이미지의 어떤 특성 → 불변 특징이 (공통 특징) / 이미지 색? 변화 → 건물로 쌓여있는 ! 
- 초창기 방식에는 백본 → fine tuning → 레이블된 데이터만으로 학습할 수 밖에 없어서, 소스 도메인이 좀 편향될 수 있다는 문제 → VLM과 같이 일부분 파라미터 업데이트 ? → 잘 일반화된 특성을 추출한다는 이점을 가져가는 메소드가 있었음. 
- 여전히 파라미터를 학습시킨다던디 일반적인 피쳐를 뽑는 것이 레이블된 것에서만 가능함.

## 제안하는 것
- 도메인 어댑터, 피쳐에 따라 인코더마다 도메인 어뎁터를 붙이는 형식임.  이 두가지 어뎁터에서 특성을 추출 → 타겟 도메인에 관한 유용한 정보를 ?
- 도메인 고정 어댑터 → 도메인 표현에 적합하도록, 다운 프로젝션/업스케일링 → 도메인 불필요 정보 제거
- 도메인 특징 어댑터 → 원 데이터 고정 정보를 빼면, 놓친 정보를 활용해서 타겟 데이터에서도 잘 활용해서 일반화가 잘 되는 것
- 비쥬얼 텍스쳐 어댑더 → VLM을 통해서 이미지를 반영한 텍스쳐 임베딩을 통해서 성능을 높일 것 !
- 텍스트를 생성하는 것인가 ?
- 공통적인 특성을 갖도록 만들어내는 !
- 입력을 토큰 → MLP → 텍스트 임베딩을 생성하는데 
- 도메인 특징 어댑터가 2개인 이유가
- 경쟁적 학습 톰은 제리를 더 잘잡게, 제리는 잘 도망치도록. 
- 도메인 스페시픽 어댑터의 로스 → 실제 정답과
